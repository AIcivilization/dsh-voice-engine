# S03 改稿增量重配

已经做过工程，用户要改其中几句。

1. **找工程。** `voice_project`，`action=list`。只有一个就用它，有多个不确定时问用户。然后 `action=show` 看句子和编号。
2. **改。** `action=edit`，只传要改的句子：
   - 改文字：`{"id":"s3","text":"新文字"}`
   - 这句换一个角色说：`{"id":"s3","vcn":"…"}`。只在用户要多角色时用
   - 删除：`{"id":"s3","op":"delete"}`
   - 新增：`{"id":"s3","op":"insert","text":"…"}`，插到 s3 后面
   - 读音不对：传 `glossary`，不要改文稿

   **「语气再正式点」这类要求，只能靠改文字实现。** 比如把「感谢每一位用户的信任」改成「谨向每一位用户致以诚挚的谢意」。不要用语速、音调、音量或换音色来表现语气：单独调一句，听起来像换了个人，工具也不允许。用 `edit` 返回的内容把改前改后告诉用户。文字不方便改时，先问用户。
3. **重配。** `action=build`。只重新合成变了的句子，其余复用，不扣量，时间轴和字幕整体重排。要沿用上次的字幕设置（`formats`、`karaoke`、`portrait`、`maxWidth`）。
4. **查结果。** `pronunciation` 只列这次变了的句子，查这些就够了。再看时长和覆盖检查。
5. **交付。** 说明重配了几句、复用了几句、扣了多少字、总时长变化。

修正最多两轮。

注意：顶层的 `vcn`、`speed`、`pitch`、`volume` 对整个工程生效，改了要重配很多句，字数会多。先用 `action=diff` 看影响，字数多就先告诉用户。

验收：只有改过的句子重新合成；字幕和新音频对得上。
