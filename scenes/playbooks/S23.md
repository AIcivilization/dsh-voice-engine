# S23 按场景推荐音色

用户描述用途，由你来挑候选，这是模型的判断，不是关键词匹配。

1. 先理解用途：内容类型、受众、语气、语种或方言。信息够用就不要追问。
2. 调用 `voice_voices`，多筛几次，比如分别用 `scene`、`gender`、`query`。官方的场景标注很粗，音色名本身也是线索，比如「大气宣传片」「旁白男声」「午夜电台」。
3. 优先选 `status=ok` 的音色。推荐 `unknown` 或 `denied` 的音色时要说明。
4. 挑 3 个风格有差别的候选，每个用一句话说理由。理由要说它和这个用途的关系。你没有听过这些音色，不要编造听感，比如「声音温暖」；只能依据名字和官方标注，并说明要听了才知道。
5. 调用 `voice_voices`，`action=present`，传这 3 个编码和 `sampleText`（用用户文案里的一句），让用户在界面上试听并点选。
6. 用户选定后继续原来的任务。如果界面不可用，就调用 S22 生成对比音频。
