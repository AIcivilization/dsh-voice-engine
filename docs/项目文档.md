# dsh-xfyun 项目文档

> 讯飞语音能力接入 dsh 的插件项目
> 文档版本 1.0 · 2026-11-03 · 状态：v0.1 音色页已完成

---

## 一、项目概况

### 1.1 这是什么

一个 dsh 插件，把科大讯飞（iFLYTEK）的语音能力接进 DeepSeek Harness，目标是让用户在 dsh 里更方便地用上讯飞语音。

### 1.2 为什么做这个

调研了 dsh 生态的 8489 个插件后，有三个事实决定了产品方向：

1. **讯飞在 dsh 生态几乎缺席。** 105 个语音类插件里，用讯飞 ASR/TTS 的数量是 **0**。而这 105 个插件中 63 个是朗读、49 个是语音输入——全是免费的 Edge TTS 和本地 SenseVoice，红海。
2. **没人做「音频生产资料」。** 没有一个插件能输出「音频 + 时间轴 + 字幕」这套完整交付物。
3. **讯飞 TTS 不返回时间戳。** 官方接口只给 `ced`（已合成字节数），不给时间信息。这既是最大的坑，也是别人做不好的地方——难啃的骨头没人啃。

所以定位不是「又一个语音按钮」，而是 **dsh 里的音频生产流水线**，核心卖点是「配音 + 时间轴 + 字幕一体化」。

### 1.3 一句话产品定义

> 在 dsh 里说一句话，拿到可以直接拖进剪映的音频 + 字幕。

### 4.2 合并策略：以发音人编码为主键

**这是整个数据层最重要的决策。**

名称是弱标识——有别名（「讯飞潘婷」vs「潘婷」）、有前导空格（`' 小师'`）、有后缀（「聆小琬-小男孩」vs「聆小琬」）。用它做键会漏匹配，而漏匹配的错最危险，因为看不见。

匹配优先级：

```python
# 1. 归一名称（去「讯飞」前缀 + 去空白）
cand = by_name.get(norm_name(rec['name'])) or []
# 2. 别名
if not cand:
    for alias in rec['aliases']:
        cand = by_name.get(norm_name(alias)) or []
        if cand: break
# 3. 样音文件名反查（解决「聆小琬-小男孩」这类带后缀名称）
if not cand:
    cand = by_file.get(norm_name(rec['name'])) or []
```

文件名反查的实现：

```python
def filename_bases(url):
    fn = url.split('/')[-1]
    base = re.sub(r'\.\w+$', '', fn).replace('%20', ' ').strip()
    base = re.sub(r'^\d+[-_]', '', base)     # 去掉「8-」这类序号前缀
    out = [base]
    head = re.split(r'[-_]', base)[0].strip()
    if head and head != base:
        out.append(head)
    return out
```

### 4.4 数据质量：发现的问题与修复

初次合并时统计出「黄金子集 97 个」，这个数字是错的。逐项排查发现 7 类问题：

| # | 问题 | 数量 | 处理 |
|---|---|---|---|
| 1 | 别名不统一（「讯飞潘婷」vs「潘婷」） | 26 条 | 自动修：去前缀 + trim |
| 2 | 名称带前导空格 | 3 条 | 自动修 |
| 3 | 拼音字段拼了「名称+风格+场景」 | 121/121 | 重算，只由 name 生成 |
| 4 | 分类口径冲突（多语种 vs 通用） | 55 条 | 以官方为准 |
| 5 | 声线粒度差异（女声 vs 甜美女声） | 34 条 | 保留两层字段 |
| 6 | **名称带后缀漏匹配** | 3 条 | **文件名反查** |
| 7 | 重复条目（聆小琬 / 七哥 / 超哥） | 3 条 | 隔离到 conflicts |

**第 1 条会掩盖其他错误。** 别名匹配不上时，那些条目被直接跳过，冲突看不见——修掉别名后分类冲突从 33 条涨到 55 条。**看不见的错才是最危险的。**

**第 6 条让黄金子集从 97 变成 100。** 漏掉的 3 个音色（如 `x4_lingxiaowan_boy`）名字带后缀，按名称匹配对不上试听台的「聆小琬」。文件名反查后补回。

第 3 条的后果：`p` 字段存 `lingfeizheqinqienanshengyuyinzhushou`，导致搜 `yuyin` 命中所有「语音助手」分类的音色。拼音索引必须只由名称生成。

### 5.2 交互设计决策

**为什么合并成一个页面而不是试听台 + 对照表两个页面**

1. 它们是同一批实体的两个视图，不是两个功能
2. 真实动线是「听 → 查 → 定」：听中一个，然后想确认它能不能用（有没有编码、要不要开通），再选定。分开就要来回切页，还得靠记忆对上名字
3. 两份数据必然再次跑偏——现在已经跑偏过 7 类问题

**为什么可用性徽标是页面的灵魂**

🟢 能听能用 / 🟠 仅能用 / 🔵 仅能听 / ⚪ 需开通。这一列直接告诉用户下一步该干什么。没有它，用户会在一个音色上试听半天，最后发现用不了。

**为什么默认只显示 100 个**

黄金子集是「能听又能用」的交集。默认展示它，避免用户把时间浪费在不可用的音色上。

### 5.3 技术实现

**状态管理**——单对象，改完重渲染：

```js
const S = {q:'', avail:'both', gender:'all', lang:'all', scene:'all',
           view:'cards', sel:null};
```

**过滤**——四维筛选 + 搜索：

```js
function filtered(){
  const q = S.q.trim().toLowerCase();
  return VOICES.filter(v => {
    if(S.avail !== 'all' && v.availability !== S.avail) return false;
    if(S.gender !== 'all' && v.gender !== S.gender) return false;
    if(S.lang !== 'all' && v.lang !== S.lang) return false;
    if(S.scene !== 'all' && v.scene !== S.scene) return false;
    if(!q) return true;
    return v.name.toLowerCase().includes(q)
      || v.py.includes(q) || v.pyi.includes(q)
      || v.code.toLowerCase().includes(q)
      || (v.aliases||[]).some(a => a.toLowerCase().includes(q));
  });
}
```

**播放器**——单例复用，`timeupdate` 只更新进度条不重渲染：

```js
const au = new Audio();

function togglePlay(code){
  const v = byCode[code];
  if(!v || !v.sample) return;
  if(cur === code){ au.paused ? au.play() : au.pause(); return }

  au.play().catch(() => { cur = null; playing = false; syncPlayUI(); });

```

## 六、技术决策记录

### ADR-001 用发音人编码做主键，不用名称

**背景**：名称有别名、有前后空格、有后缀。
**决策**：以 `code` 为主键，无编码时用 `name:<归一化名>` 兜底。
**后果**：别名问题从「漏匹配」变成「可自动修复」，26 条一次修完。名称相关的坑已经踩过两次（潘婷、聆小琬-小男孩），都因为这个。

### ADR-002 配音用逐句合成，不用长文本接口

**背景**：讯飞有长文本合成（万字级单次），但**不给时间戳**；在线合成单次限 2000 汉字，但逐句合成能天然拿到句子边界。
**决策**：按标点切句，逐句调 `v2/tts`，用音频字节数算精确时长。
**理由**：`时长 = 音频字节数 ÷ (16000 × 2)`，句级时间戳**零误差**——从音频数据本身算出来的，不是估的。这比事后用 ASR 反推靠谱得多。

### ADR-003 音色页合并成一个页面，内部双视图

**背景**：已有试听台（卡片）和对照表（表格）两个独立 HTML。
**决策**：合并成一个页面，顶部切换视图。
**理由**：见 5.2。两份数据必然再次跑偏。

### ADR-004 页面数据内联，不做外部请求

**背景**：235 条数据 65 KB。
**决策**：构建时内联进 HTML。
**理由**：单文件可双击打开、零依赖、无 CORS 问题。代价是改数据必须重新构建——可接受，因为有 `build_page.py`。

### ADR-005 进插件时前端重写 React，不用 iframe 包现有 HTML

**背景**：现有页面是单文件 HTML。
**决策**：插件内重写为 React 组件，现有 HTML 挂 `/xfyun/voices-legacy` 留作兜底。
**理由**：需要跟配音表单联动（选中音色直接带入 vcn 字段），iframe 会切断这个联动。

### 7.2 v0.2 实时合成试听

**目标**：在音色页上加「用我的文案试」按钮，输入一句自己的稿子，实时合成。

**为什么必须先做这个**：静态样音是讯飞固定的演示文案，听不出你的稿子读起来什么样——语速边界、长句断气、专业名词读音都测不出来。这一步把「选音色」从看样片变成真试音。

**任务**

- [ ] 讯飞控制台确认「在线语音合成」已开通，拿到 app_id / api_key / api_secret
- [ ] 写 `verify_tts.py`：单句合成，输出 PCM，打印字节数与计算时长
- [ ] 人工核对：听音频 + 比对时长是否吻合（**这一步不能跳**）
- [ ] Node 侧实现 WebSocket 鉴权（HMAC-SHA256 签名 URL）
- [ ] 页面加输入框 + 试听按钮，接 `/xfyun/tts` 路由
- [ ] 把「带入配音」按钮接到试听结果

**验收标准**

- 输入任意中文句子，3 秒内出音频
- 计算时长与音频实际时长误差 < 50ms
- API Key 不下发到浏览器（key 留 host 侧）

**技术要点**

```
鉴权：wss://tts-api.xfyun.cn/v2/tts，HMAC-SHA256 签名
请求：{"common":{"app_id"},"business":{"aue":"raw","vcn":"x4_lingfeizhe_zl","speed":50},
       "data":{"status":2,"text":base64(文本)}}
响应：data.audio（base64 PCM 片段），data.status（1=合成中，2=结束）
```

### 7.3 v0.3 配音 + 时间轴 + SRT（核心）

**目标**：文案进来，音频 + SRT + manifest 三件套出去。

**任务**

- [ ] `segment.js`：按标点切句，保留原文偏移，每句 < 8000 字节
- [ ] `timeline.js`：逐句合成 → 字节数算时长 → 累加得 bg/ed
- [ ] `audio.js`：PCM 直拼、句间插静音、ffmpeg 转 mp3
- [ ] `srt.js`：输出 SRT / ASS / VTT
- [ ] 并发控制 + 失败重试 + 断点续传
- [ ] 词级时间戳（三档：比例分配 / lfasr 对齐 / 超拟人 spell）

**验收标准**

- 500 字文案 → 音频 + SRT，字幕时间轴与音频对齐（人工抽查 5 句，误差 < 100ms）
- 生成的 SRT 能直接拖进剪映使用
- 中途断网重跑，已完成片段不重复合成

**时间轴算法**

```
文本 → 按标点切句（每句 < 8000 字节）
     → 逐句调 v2/tts（PCM 16k/16bit/mono）
     → 每句时长 = 音频字节数 ÷ (16000 × 2)
     → 累加 + 句间停顿 → 每句 bg / ed
     → 拼接 PCM → 单次编码为 mp3
```

**词级时间戳三档**

| 档位 | 方法 | 精度 | 成本 |
|---|---|---|---|
| 快（默认） | 句内按字符加权（逗号 1.5×、句号 2×） | ±150ms | 0 |
| 准 | 整段送 lfasr 取 `wordBg/wordEd`（10ms/帧），与原文字符对齐 | ±30ms | 转写费 |
| 巧 | 超拟人二进制模式 `data.spell`（拼音序列）辅助 | ±80ms | 0 |

### 7.4 v0.4 缓存与增量重配

**目标**：改一句文案只重合成那一句。

**任务**

- [ ] 片段 key = `sha256(文本 + 音色 + speed/pitch/volume + 接口版本)`
- [ ] 片段音频落盘 `~/.dsh/dsh-xfyun/cache/`
- [ ] 时间轴整段重排（纯计算，毫秒级）
- [ ] manifest 记录每句的 key，改稿时 diff 出变动句

**验收标准**

- 100 句文案改 3 句，只发 3 次请求
- 重配后时间轴自动重排，SRT 正确

## 八、风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| **讯飞需实名 + 付费** | 无法开发调试 | 新用户有 1 万次交互 / 50 小时转写免费额度，够开发期 |
| **并发限制** | 逐句合成会打满 QPS | 内部队列 + 指数退避 + 可配并发数 |
| **声音复刻合规** ⚠️ | 克隆他人声音涉声音权，国内已有判例 | 强制授权勾选 + 水印/元数据标记 + README 显著声明 |
| **样音 CDN 防盗链** | 页面集体放不出 | 首次播放后落盘缓存到 `~/.dsh/dsh-xfyun/audio/` |
| **时间戳精度预期** | 用户误以为词级精确 | 输出标注精度等级，精细场景引导开 `--precise` |
| **免费方案竞争** | Edge TTS 免费且够用 | 不打价格战，打「质量 + 交付物完整度」 |
| **讯飞接口变更** | 字段/限额调整 | 版本探测 + 降级到长文本接口（牺牲时间轴） |

**外部依赖**

- 讯飞开放平台账号（已实名，TTS / 复刻 / 转写三个服务需分别开通）
- `ffmpeg`（音频转封装、视频抽音轨）
- `pypinyin`（数据构建时用，运行时不需要）
